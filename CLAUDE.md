# CLAUDE.md

Guidance for coding agents working in this repository.

## Project

Fluency Lab: an app to practice English by writing. The user chats
about anything or picks a suggested topic; every session saves
mistakes, new words and progress, and the suggestions get better with
use. Following a plan is optional; free practice is the default.

Status: fresh Expo project. The screen map, the palette and the Home
design are decided (see README.md). No screen is built yet.

## Stack

- Expo SDK 58, Expo Router, TypeScript strict, React Compiler on. Runs
  in Expo Go.
- A single app, not a monorepo. Routes live in `src/app/`.
- pnpm is the only package manager. Add Expo packages with
  `pnpm expo install <package>`, never with npm or npx. AGENTS.md was
  generated by Expo and shows `npx`: read it for Expo guidance, but run
  every command through pnpm.
- AI with the user's own key (Claude or OpenAI), with a monthly spend
  limit set by the user.
- Sign in with Google, Apple and email.
- Text only: no voice.
- Tests: jest-expo for the app; `node --test` for the repo scripts, in
  `scripts/test/`.
- Hooks with lefthook, commit messages with commitlint.

Pending decisions, not to be assumed: the backend for accounts and
progress, and the folder layout inside `src/` beyond `src/app/`. An
issue that needs one of them stops and asks.

## Commands

    pnpm install                 also installs the git hooks (lefthook)

    pnpm start                   Expo dev server
    pnpm gate                    typecheck, lint and test; what scripts/ship.sh runs
    pnpm typecheck               tsc --noEmit
    pnpm lint                    eslint + prettier --check
    pnpm test                    jest, then node --test over scripts/test
    pnpm exec jest <path>        one test file
    pnpm format                  to fix formatting

Hooks: pre-commit runs eslint and prettier on the staged files,
commit-msg runs commitlint, pre-push runs typecheck and test. CI runs
the whole gate and is not skippable.

## Hard rules

- Reusable and centralized: shared components and one source for
  colors, sizes, spacing, radii and fonts. No visual value written
  inline in a screen.
- Logic lives in pure functions, outside components. A component calls
  them and draws the result.
- TDD: the test is written first, and ships in the same branch as the
  code.
- The AI provider, auth, the backend and storage go through a small
  interface (a port). Screens never call a library or build a URL.
- Zero secrets in the code. The user's API key is stored only in the
  device's secure storage and never logged, sent anywhere else or
  written to a file.
- No attribution to tools or AI anywhere: not in commits, pull
  requests, code, comments or docs. No `Co-Authored-By`, no
  "Generated with". commitlint rejects it.
- No `any`, explicit or via a cast. No `console.*` left in the code.
- No `catch` that swallows an error and returns an empty value or a
  success. A failure reaches the screen as a typed outcome.
- An expected empty state (no sessions, no mistakes) is a value, not an
  error.
- No `useMemo`, `useCallback` or `memo` unless the line above says why
  the React Compiler is not enough.

## Definition of done

A screen is done when:

1. Every state is drawn: loading, with data, expected empty, error.
2. Its logic is in pure functions with tests: normal case, empty case,
   edges.
3. Every outside call has its four tests: success, expected empty, a
   failure the screen branches on, transport failure.
4. Every visual value comes from the shared tokens.

See `docs/testing.md`.

## Workflow

Work goes through the agent loop: the agents in `.claude/agents/`, the
skills in `.claude/skills/` and the scripts under `scripts/`. The
orchestrator dispatches each stage by name with a one-line prompt
(issue number, plan path, mode), does not read the agent definitions
and does not implement.

    create-issue (skill)    only to open a new issue
    refine-issue (skill)    only when the issue lacks scope, out of scope
                            or acceptance criteria
    plan-issue              only when the issue touches app logic or a
                            screen; then the owner approves the plan
    implement-issue
    scripts/loop-path.sh    prints short or full
      short -> ship
      full  -> review-changes -> verify-findings (only on Blocking or
               Important findings) -> implement-issue (fix mode) -> ship
    ship (prepare) -> the owner approves the body -> ship (publish)

Scope freeze: the scope is the issue body when the loop starts. What
comes up mid-loop is a new issue, not an addition to the running one.

Gate: `pnpm gate`. `implement-issue` runs it once, when the plan is
implemented; if it fails, it fixes and reruns, at most three attempts,
then stops and reports. `scripts/gate-limit.mjs`, a PreToolUse hook
declared in `.claude/settings.json`, enforces the limit.

Only `scripts/ship.sh`, driven by the `ship` skill, creates branches,
commits, pushes and opens pull requests, and only when the owner
invokes the skill. Agents never push and never merge.

Branches: `w_<YYMMDD>_<type>_<desc>`. Run `date` before naming one.
Commits: conventional commits, `type(scope): description`, one line,
no body. The reasoning goes in the pull request. Pull requests target
`main`, close their issue with `Closes #N` and are squash merged.

The full flow, step by step, is in `docs/workflow.md`.

Decisions and merge: the repo owner.

## Review

`review-changes` applies these in the full loop. Formatting and lint
are not flagged: the gate covers those.

Blocking:

- A secret or the user's API key in code, logs, tests or fixtures.
- Any attribution to tools or AI.
- A library or a network call used directly in a screen instead of
  through its port.
- A color, size, spacing, radius or font value written inline instead
  of coming from the shared tokens.
- Logic inside a component that should be a pure function.
- Code without its tests, or tests written after the fact that only
  mirror the implementation.
- A `catch` that swallows an error and returns an empty value or a
  success.
- An expected empty state treated as an error.
- A `useMemo`, `useCallback` or `memo` without the comment that says
  why.

Important:

- `any`, explicit or via a cast.
- `console.*` left in the code.
- A screen shipped without one of its states.
- A copy of a component instead of reusing the shared one.
